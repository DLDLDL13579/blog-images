## 关键实现：外链引用机制

本仓库没有代码，唯一的「实现」是**约定**：博客文章不上传图片，而是引用 GitHub raw 地址，由博客平台在渲染时加载。

```markdown
![图注](https://raw.githubusercontent.com/DLDLDL13579/blog-images/main/<分组>/<文件名>)
```

```text
https://raw.githubusercontent.com/DLDLDL13579/blog-images/main/<分组>/<文件名>
```

其中 `DLDLDL13579/blog-images` 为仓库全名、`main` 为元数据给出的默认分支，`<分组>/<文件名>` 必须替换为仓库中真实存在的路径。**事实包只列出了目录名和数量，没有列出 45 个文件名，因此本文无法给出可直接复制的完整 raw URL**；写文章前先在仓库里确认文件名。

这样设计的原因：把图片从文章仓库剥离，文章仓库不随截图反复膨胀，同一张图可被多篇文章复用；代价是文章渲染依赖 `raw.githubusercontent.com` 可达，且链接与分支名、文件路径强绑定（见「已知问题」）。

## 快速开始

前置条件：只需能访问 `raw.githubusercontent.com` 的浏览器或博客平台；**不需要** Node、Python、ROS、任何包管理器或构建工具。

```bash
# ① 取回仓库（clone 地址由全名推出）
git clone https://github.com/DLDLDL13579/blog-images.git
cd blog-images

# ② 按事实包给出的分组名查看实际文件名，替换成文章要用的真实路径
ls dwb-velocity-scoring/
ls nav-quant-20261023/

# ③ 在文章中按上一节的模板拼出 raw URL 并引用
```

引用前建议核对两点：① 文件是否真实可读（不是文本指针），若打开只有短短一行指针文本而非图片数据，说明需先执行 `git lfs pull` 取回真实文件；② 文件体积是否适合博客加载。**事实包未提供任何逐文件体积，本仓库是否使用 Git LFS、是否存在指针文件均无法确认**，以上只是通用的核对步骤，不是对仓库现状的断言。
